Front end storyboard
eleven screens, and what each one is for

GAMEDESIGN §9 lists the screens and the order a first-time player meets them. This sheet fixes what information lives on each one and what it is called. It fixes nothing about how any of it looks.

Why this is drawn in hairlines read before reacting

Every box below is a dashed rectangle with a monospaced label in it, and that is a decision rather than laziness. A mockup that looked good would become the design by accident — and the visual pass is blocked on references, not on effort: paddocks, live timing screens, classification sheets, number panels on a moving kart. The telemetry HUD is the worked example of doing it properly. Its layout came off a photograph and contradicted reasoning in five separate places, starting with the fact that a real kart dash is a positive LCD rather than glowing white on black.

So react to the hierarchy: what is on each screen, what is missing, what is one screen that should be two. Colour, type and texture come after the reference photographs land.

Revision 3. Eighteen decisions are settled and recorded as ADR-0052; the settled ink below says which. The mode screen is deleted — its plate is gone and the flow is one step shorter. Two things remain open on purpose: tuning-overlay access, decided by playing it, and naming.

01

Boot

Proves the game launched: the extension loaded, the kart asset exists, the audio device opened. Anything missing is said here in words, not as a silent black screen.

  • The game is launched by double-clicking it. project.godot gains a main scene, which it has never had.
  • Any key or any pad button continues. No timed splash.
  • On a missing generated asset, boot refuses and prints the exact command. No offer to run the generator — that bakes a Blender dependency into the shipped game, and this state is a dev-checkout condition. ADR-0052.

02

Paddock — the main menu

Diegetic, per §7's fiction level — and now literally a place: a generated 3D paddock behind document-styled UI, built in stages starting from a vignette (kart on a stand, an awning, a parked camera). Three modes on the left, your standing in the world on the right.

  • The backdrop is a generated 3D environment through the kart's own Blender pipeline, staged — vignette first, environment growing outward in later rounds. ADR-0052.
  • There is no mode screen. The modes sit here, each saying what it is in one line. ADR-0052.
  • An unbuilt mode is visible and states its precondition — "needs a field — M7" — where a released build would put a difficulty hint. Neither absent nor a greyed row that does nothing. ADR-0052.
  • Exactly one focused thing per screen; hovering the pointer moves the focus ring rather than lighting a second state. ADR-0045.
  • The footer names the detected pad and its real bindings — control_hints.gd already does this in the driving scenes.
  • Career with no profile creates one — the four-question first-run sequence is the career's own first step. Signing an entry form is diegetic; no lock state. ADR-0052.
  • On a first run, "where you are" is an invitation: one authored line per empty slot, in the world's voice — "No entry filed — the OK season starts when you do." Not blank dashes, not a hidden panel. ADR-0052.

03

Session setup

Fills in a SessionConfig and nothing else. The right column is the configuration read back as it will be recorded — the same fields, the same hash a replay compares first.

  • Every row here is a real field of the committed type, and the screen cannot invent one. KartSession.field_names() is fourteen entries.
  • Assists default on, greyed but reachable. Issue #40.
  • The config hash is hidden, one keypress away — a debug-family toggle plus "copy session info" on results. A player never parses hex; a bug report never loses its best line. ADR-0052.
  • One setup screen for all four session types. A weekend renders circuit, layout and class read-only where the round decides; what a real entrant chooses — assists, preset, ghost — stays live. ADR-0052.

04

Loading

A real progress count over real steps, and one line about the circuit you are about to drive.

  • Steps are named, not a spinner. The first headless import of a cold project takes long enough to look like a hang.
  • The tip line stays, corpus-gated: lines are authored from measured facts only — §6.4 figures, corner behavior, class differences — and if the pool is thinner than about twenty real lines at ship, the row is dropped rather than padded. ADR-0052.

05

Grid and countdown

A race state. Practice has no grid and no countdown, and the runner does not pretend otherwise — it starts the kart on track and the first lap is an out lap.

  • The first lap of a session can never become a best lap. A timer that trusts its own zero records a 24 s record nothing can beat.
  • Race states are configurations of the one runner, not a second mode. This is why the runner was written before the cameras.
  • Practice cuts straight from loading to driving — no countdown, no grid card. The kart is placed rolling at the pit exit; the first lap is an out lap and can never be a best. ADR-0052.

06

Driving

The one screen that already half-exists. Timing on the left, the dash bottom-right, the ghost delta opposite the timing so the two numbers a driver reads are not in the same corner.

  • Lap times as m:ss.mmm, deltas signed with negative ahead.
  • A struck-out lap says why — off track, missed a checkpoint, respawned — because "invalid" with no reason is a driver arguing with the game.
  • Nothing is printed here that the input map does not really bind. Four control failures in one day is why (#169).
  • The delta is against the selected ghost and labeled as such. Identical to "own best" in Practice today; the definitions diverge the moment a ghost can come from another session, and the HUD follows the ghost it draws. Sector deltas vs session best stay a separate channel. ADR-0052.
  • When may the tuning overlay be opened in a shipped build? Deliberately undecided until it has been driven with — Anthony has not yet used F2, and the design's own precedent is "decide it by playing it".

07

Results

What the session produced. In Practice that is a best lap, its splits, the theoretical optimal, and the whole session under it.

  • The optimal lap is shown next to the best and is never presented as a lap time — it is the sum of sector bests and nobody drove it.
  • "Saved" appears only after the write succeeded, and the write is atomic.
  • Every lap is listed, scrollable, best and optimal pinned above the scroll. Struck laps carry their reason. A real classification sheet is the whole session on one page. ADR-0052.

08

Standings

The whole of the fiction, per §7: an entry list, real columns, and a table that does the storytelling no text has to.

  • Columns off the real published entry list: Surname, Forename; two nationalities, driver and entrant, which routinely differ; chassis / engine / tire as one slash-joined string.
  • Points come from three classifications a round, not just the Final, so a bad Final does not erase a good day.
  • Promotion at top 3, and the gap to it is stated rather than left to arithmetic.
  • Both nationality columns and the equipment string stay — the full real column set. Equipment compresses to chassis / engine; the tire is a mandated control tire, uniform down the field, and drops to a footnote. ADR-0052.

09

Pause

Four items. The right half exists because a paused kart that is still simulating needs to say so, and because the lap you were on is about to be worthless.

  • Pause gates input at PlayerDriver, not by freezing the body. ADR-0040 is what made that a one-line call.
  • Invalidation is a player option, default on, living with the assists — and a best lap set with forgiveness enabled is flagged on the saved record, or every best silently absorbs an advantage the screen never mentions. The timing line here states the consequence either way. ADR-0052.
  • One clock rule: Practice has no session clock, so the question is moot there; in timed sessions the session clock keeps running under pause, as in the real thing — pausing costs track time. ADR-0052.

10

Settings

The §18 comfort options, the bindings, the assists. All of them exist as values in the code already and none of them can be reached by a player today.

  • One grouped list under section headers, single scroll — no tab strip, no second navigation axis on a pad. The interaction is the one the tuning overlay already taught. ADR-0052.
  • The pause-invalidation option lives here with the assists. ADR-0052.
  • Its own file. A career save that will not parse must still leave a menu you can read and a pad you can use — which means settings load when the career does not.
  • Menus declare their own menu_* actions. The engine's ui_* defaults are bound to the arrow keys, and the arrow keys are already throttle, brake and steer.
  • Audio is a section here — master, effects, engine — stored in settings.cfg, and the level probe reads the stored values, so the audit still sees what the player moved. Player-facing and measurable are not in conflict. ADR-0052.

11

Profile

Who you are, and everything that survives a quit. Name in the sport's own format, a number from the class's real block.

  • Numbers come in per-category blocks — 1xx for OK — and are fixed for the season, so the entry list reads as one document rather than the player plus some AI.
  • A best lap is stored per track per layout per class, or a shifter time silently beats a single-speed one.
  • The name is typed: surname and forename as two fields, rendered "Surname, Forename" everywhere the entry list does it, empty refused. A name picker defending the fiction against its one human participant defends it from the wrong direction. ADR-0052.

and one that is not a design question

Every screen above needs reference photographs before it gets a colour or a typeface: paddocks, live timing boards, printed classification sheets, number panels on a moving kart — and now the paddock's own geometry: awnings, kart stands, tire stacks, trailers, the ground between them.
